Autonomous Coding Agents Put Open-Source Pull Requests Through Provenance Test

Autonomous coding agents are scaling open-source contributions, but merge workflows, incomplete disclosure, and uneven attribution make provenance a governance test, not merely a detection problem.

September 2, 2026 · 12:02 PM PDT · 7 min read · 12 sources · Original family: Autonomous AI Code Agents
coding agentsopen sourcesoftware supply chainprovenance
Editor’s brief

Why this matters now

The supplied evidence points to a rapidly expanding but difficult-to-measure contribution channel. Studies report agent-assisted commits that are larger than human-only commits, substantial differences between agentic and human pull requests, and a dataset of 33,596 agentic pull requests spanning five major coding agents. Another source reports agent-linked activity across one million repositories rising from 2% in October 2025 to 10% in May 2026, although the supplied material does not describe enough methodology to compare that estimate directly with the academic datasets.

The central issue is provenance: whether maintainers can identify how a change was produced, who or what should receive attribution, and what evidence supports review. The sources show that attribution depends heavily on workflow. Squash merges can erase agent identity from commit records, direct commits may retain author-level signatures, and at least one study limited its sample to pull requests explicitly marked as generated with Claude Code. These constraints mean observed pull-request counts and attribution signals should be treated as partial views rather than complete censuses.

Assignment angle: This angle examines whether autonomous agents can meet emerging software-provenance and maintainer-attribution expectations when submitting code at scale.

FIELD NOTE

Scale Is Growing, but Measurement Is Fragmented

The evidence establishes meaningful agent activity in open-source workflows, but not a single agreed measurement of its scale. One study analyzes 33,596 pull requests attributed to OpenAI Codex, GitHub Copilot, Devin, Cursor, and Claude Code, with metadata covering agent names, timestamps, commits, and authors. Another study reports that agent-assisted commits are larger than commits authored only by human developers and contain a large proportion of features and bug fixes.

A separate report says agent-linked code appeared in 2% of one million repositories in October 2025 and 10% in May 2026. Because the supplied snippet does not provide the report's full methodology, this result is best read as an additional signal of growth, not as a directly comparable estimate. The studies collectively support expansion, while leaving uncertainty about coverage, definitions, and detection completeness.

  • Agentic pull-request datasets can be large enough to support repository-scale analysis.
  • Commit size and feature or bug-fix composition differ between agent-assisted and human-only commits.
  • Reported prevalence depends on the detection method and population being measured.

FIELD NOTE

Merge Workflows Can Erase Attribution

The strongest provenance problem in the supplied evidence occurs at the boundary between agent execution and repository history. One census reports that Codex and Cursor work commonly lands through squash-merged pull requests, which erase agent attribution from the commit record, while Claude Code and Devin can appear through direct commits with author-level signatures. The same source says a pull-request census misses a substantial share of commit-detected repositories within its stated comparison window.

Disclosure is also selective. A study of Claude Code usage notes that developers may generate code with the tool and then push changes directly without asking the tool to perform the commit. To mitigate that problem, the researchers included only pull requests clearly marked as generated with Claude Code. This improves the study's internal precision but also demonstrates why visible attribution cannot automatically be treated as a complete record of agent use.

  • Squash merging can preserve review context while removing agent identity from commit metadata.
  • Direct commits and pull-request descriptions expose different provenance signals.
  • Explicit disclosure requirements can reduce false positives but may exclude undisclosed usage.

FIELD NOTE

Pull Requests Reveal Change Patterns, Not Full Responsibility

The supplied pull-request studies provide useful evidence about the shape of agentic work. One reports substantial differences from human pull requests in commit count, with moderate differences in files touched and deleted lines, and slightly higher description-to-diff similarity across its measures. Another constructs a filtered dataset of 7,156 pull requests from permissively licensed repositories and requires at least one review or comment from someone other than the creator before closure.

These designs make comparison more disciplined, but they do not by themselves answer who should be credited for the resulting code or whether an agent's contribution can be reconstructed after later edits and merges. The review requirement establishes meaningful evaluation within the selected sample; it does not prove that every autonomous contribution received comparable scrutiny. Provenance therefore has to connect the agent run, generated artifact, human review, and final repository state rather than relying on pull-request metadata alone.

  • Agentic and human pull requests differ in several observable structural measures.
  • Quality-oriented sampling criteria can require review or comment activity before closure.
  • Change-pattern analysis is not equivalent to end-to-end authorship or provenance verification.

FIELD NOTE

Provenance Expectations Are Moving Toward Attestations

The supplied governance proposal treats AI-authored changes as artifacts from an untrusted producer and recommends proving provenance before review. It specifically describes signed attestations that can record the model, task specification, allowed tools, tests, and evaluations behind a change. That approach would give maintainers evidence about process, not only a label attached to a commit or pull request.

Another source describes a server-less Git substrate built around conflict-free concurrent edits, advisory leases, and a signed, content-addressed, mineable history. A GitHub repository listed in the supplied material similarly describes a project intended to govern autonomous coding runs with budgeted, verified work and signed outcome receipts. These are proposals or project descriptions in the supplied evidence, not validation that such controls are widely adopted or effective. If implemented and accepted, they could shift provenance from an optional disclosure field toward an auditable submission property.

  • Signed attestations could bind an agent run to its task, tools, tests, and evaluations.
  • Content-addressed histories are presented as a way to make agent coordination and provenance mineable.
  • The supplied material does not establish broad adoption or independent validation of these mechanisms.

↗ Where it could go

  • Larger-scale agent contributions could increase the volume of features and bug fixes reaching open-source projects, as suggested by the commit-level findings.
  • Structured metadata and signed attestations could give maintainers more evidence for reviewing AI-authored changes than commit labels alone.
  • Cross-method studies could improve understanding of agentic work by combining pull-request, commit, author, and repository-level signals.
  • Content-addressed, signed histories could make multi-agent edits and their provenance easier to reconstruct if the proposed mechanisms gain adoption.

△ What could go wrong

  • Squash merges can erase agent attribution from commit records, weakening later accountability.
  • Studies based on explicit labels may undercount undisclosed agent use, while detection signals may not capture every workflow.
  • Pull-request statistics can describe change patterns without proving who produced, reviewed, or remains responsible for the final code.
  • Provenance controls may be proposed or listed as project goals without evidence of broad adoption or independent validation.

◌ Watch next

  • Whether major repositories preserve signed, machine-readable attestations across squash merges and other integration workflows.
  • Whether agent submissions consistently disclose model identity, task specification, allowed tools, tests, evaluations, and human review.
  • Whether future censuses reconcile pull-request detection with commit-level detection instead of treating either channel as complete.
  • Whether maintainers adopt explicit attribution and provenance requirements for autonomous submissions at scale.
Closing read

Conclusion

The evidence supports a factual conclusion that autonomous coding agents are contributing at meaningful scale and that their changes exhibit measurable differences from human pull requests and commits. It also supports a second conclusion: repository history is not a reliable, uniform provenance layer. Squash merges, direct pushes, selective disclosure, and detection-method differences can all change what maintainers are able to see.

The stronger claim—that autonomous agents will meet emerging software-provenance and maintainer-attribution expectations—remains a projection. Signed attestations, content-addressed histories, and verified outcome receipts are described as possible controls or project goals, but the supplied sources do not demonstrate ecosystem-wide adoption or effectiveness. The practical test will be whether maintainers can independently connect each submitted change to its producing agent, instructions, tools, tests, evaluations, human review, and final merged artifact.

Five takeaways

  • Agent-assisted commits are reported as larger than human-only commits and contain a large proportion of features and bug fixes, but the supplied evidence does not establish causation.
  • A dataset of 33,596 agentic pull requests covers five named coding agents and includes authorship, timestamps, commit, and agent metadata.
  • Squash-merged workflows can erase agent attribution, while direct-commit workflows may retain author-level signatures; observed provenance depends on integration path.
  • A filtered study of 7,156 pull requests required permissive licenses and independent review or comment activity, showing how methodology shapes quality comparisons.
  • Signed attestations and content-addressed histories are proposed provenance mechanisms, but the supplied sources do not prove ecosystem-wide adoption or effectiveness.
