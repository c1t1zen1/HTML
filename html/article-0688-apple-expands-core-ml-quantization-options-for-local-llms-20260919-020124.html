FIELD NOTE

What Quantization Actually Does

Large language models store their parameters as floating-point numbers, typically in BF16 (Brain Float 16) format, which uses 2 bytes per parameter. A 70B parameter model therefore occupies approximately 140GB in BF16 precision. Quantization reduces the precision of these numbers, compressing storage requirements while attempting to preserve model accuracy. The tradeoff is straightforward: lower precision means smaller models that fit in less memory, but potentially greater accuracy loss.

  • BF16 (16-bit) is the default precision for most large models
  • INT8 uses 1 byte per parameter, halving memory requirements
  • INT4 uses 0.5 bytes per parameter, quartering memory requirements
  • FP8 offers an alternative 8-bit floating-point format

The Accuracy-Speed Tradeoff

The quantization debate centers on balancing model size against accuracy loss. INT8 quantization is generally considered production-ready with minimal accuracy loss and 4x memory reduction. INT4 offers more aggressive compression with 8x memory reduction, but typically introduces more quantization error. Research shows that 4-bit quantization can cause noticeable drops in model performance, particularly on specialized tasks like Chinese language evaluation and instruction following.

  • INT8: production-ready, minimal accuracy loss, 4x memory reduction
  • INT4: aggressive compression, 8x memory reduction, acceptable for most use cases
  • Q4_K_M dropped 15-20% on C-Eval (Chinese evaluation benchmark)
  • Instruction following (IFEval) lost over 10% at INT4 precision

Advanced Quantization Techniques

Several sophisticated quantization methods have emerged to mitigate accuracy loss at lower bit depths. GPTQ and AWQ are post-training quantization techniques that optimize weight compression. The GGUF container format supports multiple quantization levels (INT4, INT5, INT6, INT8, FP16) and enables CPU inference via llama.cpp. Research has demonstrated that 4-bit quantization combined with LoRA fine-tuning can match full-precision fine-tuning on many benchmarks, suggesting that aggressive compression is viable when paired with appropriate training techniques.

  • GPTQ-INT8 held closest to baseline performance for general knowledge and coding tasks
  • GGUF format supports INT4, INT5, INT6, INT8, and FP16 quantization levels
  • QLoRA demonstrated 4-bit quantization with LoRA can match full-precision fine-tuning
  • KV cache quantization to INT8 halves memory usage with little task-level impact

Implications for Mac Hardware

The significance of expanded quantization support in Core ML lies in enabling developers to run compressed models efficiently on Apple Silicon. With INT4 quantization reducing a 70B model from 140GB to approximately 35GB, such models become feasible on high-end Macs with 36GB or more of unified memory. The framework-level support would abstract away the complexity of quantization format selection and dequantization during inference, making it easier for developers to deploy optimized models without deep expertise in compression techniques.

  • 70B model in BF16: ~140GB; in INT4: ~35GB
  • Framework support abstracts quantization complexity from developers
  • Apple Silicon's unified memory architecture benefits from compressed models
  • CPU inference via formats like GGUF becomes more practical
